# 보유·리밸런스 탭 병합 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 보유·리밸런스 두 탭을 한 화면으로 합치고, 다중 선택을 롱프레스로 진입하는 컨텍스트 모드로 옮긴다.

**Architecture:** 탭은 두 개의 화면이 아니라 **하나의 화면 + 다중 선택 모드**였다. 목표 비중·비중바·매수매도 칩·목표 다이얼로그는 이미 두 탭 모두에서 무조건 그려지고 있었고(`HoldingDetail:796`, `HoldingRow:741`), 리밸런스 탭이 **더** 보여주는 것은 체크박스 하나뿐이며 대신 보유 명세줄을 **감춘다**. 따라서 병합은 "두 화면을 합치는" 일이 아니라 "모드 플래그 하나(`rebalanceMode`)를 선택 모드 플래그(`selecting`)로 바꾸고, 진입 경로를 탭에서 롱프레스로 옮기는" 일이다. 로직 변경은 없다 — `Rebalance.kt`(순수 계산, 테스트 45개)는 한 줄도 건드리지 않는다.

**Tech Stack:** Kotlin 2.4.10 · Compose BOM 2026.08.00 (foundation 1.12.0) · Material3 · Koin 4.2.2 · DataStore · detekt 1.23.8 · ktlint-gradle 14.2.0 · JDK 21 · minSdk 31

**Spec:** 사용자 요구 3항목(아래 "요구사항 원문") + `design/Main.dc.html`(승인된 시안) + `design/canvas.json`

## 요구사항 원문

사용자가 지정한 세 가지다. 이 계획은 전부를 덮는다.

1. 롱프레스하면 다중 선택 모드가 되도록 변경
2. 롱프레스 모드에서 **전체 선택, 선택 개수, 선택 취소, 목표 지우기, 목표 설정** 메뉴가 나타나도록 함
3. 두 탭을 합치는 것에 맞춰 **코드, 시안**도 수정

## Global Constraints

프로젝트 전역 제약이다. 모든 태스크의 요구사항에 암묵적으로 포함된다.

- **거래 기능은 절대 구현하지 않는다.** 매수/매도 수량 표시까지가 끝이다.
- **새 의존성 금지.** 이 계획에 필요한 `combinedClickable`(foundation 1.12.0)과 `BackHandler`(activity-compose 1.13.0)는 **이미 있다** — 아래 "사전 검증"에서 확인 완료.
- **Kotlin only.** XML 레이아웃·Java 파일을 만들지 않는다.
- **로그·문서·오류 메시지·커밋에 키·토큰·계좌번호·PII 금지.**
- **사용자에게 보이는 모든 문자열, 주석, 커밋 메시지는 한국어.** 화면에 영어 내부 라벨(`token`, `error` 등)이 나가면 실패다.

- **`git push`는 명시적 지시가 있을 때만.** 커밋은 태스크마다 한다.
- 접근성은 단순화 대상이 아니다. 롱프레스에는 반드시 TalkBack 대체 경로를 붙인다.

## 확정된 설계 결정

구현자는 아래를 재논의하지 말고 그대로 따른다. 각 결정에는 이유가 붙어 있다.

**D1. `selecting` 은 `selected.isNotEmpty()` 로 유도하지 않고 별도 `Boolean` 으로 둔다.**
유도하면, 체결 통보로 잔고가 갱신되어 고른 종목이 목록에서 빠질 때 선택이 비고 **모드까지 조용히 꺼진다.** 편집 중에 상·하단 바가 통째로 사라지는 동작은 받아들일 수 없다. 별도 플래그면 "0개 선택"으로 남는다.

**D2. 선택 모드에서 행 탭 = 선택 토글, 롱프레스 = 선택 모드 진입/추가.**
안드로이드 관례다. 탭이 목표 다이얼로그를 계속 열면 작은 체크박스만이 유일한 토글 표적이 되어 44dp 기준을 못 채운다.

**D3. 예수금 행은 선택 대상이 아니다 — 롱프레스·탭 모두 반응하지 않는다.**
예수금 목표는 `Rebalance.scaleForCash` 비례 조정 경로를 타야 하며 일괄 설정 대상이 아니다(`setTargets` 가 `require` 로 막고 있다). 체크박스가 없다는 사실이 이미 시각적으로 설명하므로 별도 안내를 붙이지 않는다.

**D4. 보유 명세줄에 `maxLines` 를 걸지 않는다 — 줄바꿈을 허용한다.**
주식수·평균매입가·현재가·잔고수량은 사용자가 명시한 **요구 항목**이다. 폰트 배율 1.3 이나 8자리 가격에서 잘라내면 요구 데이터가 사라진다. 행이 한 줄 높아지는 편이 낫다.

**D5. 선택 취소는 상단바 `X` 하나로 둔다 — 하단바에 중복 버튼을 두지 않는다.**
요구 2항의 "선택 취소"는 이 `X` 가 충족한다. `contentDescription = "선택 취소"` 로 TalkBack 에도 그 이름으로 읽힌다.

**D6. 목표 지우기·목표 설정은 선택 0개일 때 `enabled = false` 로 남긴다 — 숨기지 않는다.**
요구 2항이 "메뉴가 나타나도록"이라고 했다. 사라지면 무엇이 가능한지 알 수 없다.

**D7. 새 단위 테스트를 만들지 않는다.**
이 변경에는 순수 계산 로직이 없다. 금액이 틀릴 수 있는 코드(`Rebalance.kt`)는 한 줄도 바뀌지 않고 이미 45개 테스트가 덮는다. 델타는 전부 상호작용이며, 이 프로젝트는 Compose UI 테스트를 쓰지 않기로 **사용자가 결정**했다. 억지 테스트 대신 각 태스크에 **기기 스모크 절차**를 정확한 기대값과 함께 적는다. 검증 게이트(109개 통과 + detekt 0 + ktlint clean)는 모든 태스크에서 그대로 돈다.

```kotlin
/**
 * 선택 모드 상단바. 계좌번호 대신 선택 개수를 걸고, 뒤로가기 자리를 나가기가 아니라 선택 취소로 바꾼다.
 *
 * 뒤로 화살표를 그대로 두면 "어디로 돌아가는지" 가 모호해진다 — 선택을 끝내는 X 로 갈라 쓴다.
 * 일부만 골랐을 때는 [ToggleableState.Indeterminate] 로 두고, 누르면 전체 선택으로 간다.
 */
@Composable
private fun SelectionTopBar(
    count: Int,
    allSelected: Boolean,
    anySelected: Boolean,
    hasSelectable: Boolean,
    onToggleAll: () -> Unit,
    onExit: () -> Unit,
) {
    TopAppBar(
        title = { Text("${count}개 선택", style = MaterialTheme.typography.titleSmall) },
        navigationIcon = {
            IconButton(onClick = onExit) {
                CloseIcon(modifier = Modifier.semantics { contentDescription = "선택 취소" })
            }
        },
        actions = {
            TriStateCheckbox(
                state =
                    when {
                        allSelected -> ToggleableState.On
                        anySelected -> ToggleableState.Indeterminate
                        else -> ToggleableState.Off
                    },
                onClick = onToggleAll,
                enabled = hasSelectable,
                modifier = Modifier.semantics { contentDescription = "전체 선택" },
            )
        },
    )
}
```

## 남는 위험 (계획으로 없앨 수 없는 것)

- **발견 가능성.** 롱프레스는 눈에 보이지 않는다. 사용자가 선택한 방향이며, 이 계획은 상단바 전환과 TalkBack 라벨로 완화하지만 "이 앱이 일괄 목표 설정을 할 수 있다"는 사실을 처음 알리는 장치는 사라진다. 실사용 후 필요하면 요약 카드의 `목표 합계 · 미설정` 자리에 안내 한 줄을 붙이는 것이 가장 싼 보완이다.
- **밀도.** 모든 행이 약 91dp 로 통일된다(기존 리밸런스 탭 약 68dp — 패딩·글꼴 행높이 합산 추정치). 한 화면에 종목이 약 2개 덜 보인다. 종목이 20개를 넘는 계좌에서 체감된다.
- **명세줄 줄바꿈.** 폰트 배율이 크거나 가격이 8자리면 명세줄이 두 줄로 접힌다. 결정 D4 에 따라 의도한 동작이다.
